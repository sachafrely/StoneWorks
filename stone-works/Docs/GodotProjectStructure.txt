# Architecture rules

Scenes contain Godot scene composition and visual/physical entities. They should not own core gameplay rules.

Core coordinates the application. Game should not contain gameplay logic. GameState represents current game state. GameTime owns game-time concepts. EventBus provides event-based communication.

World owns the environment and grid-based terrain representation. The grid is gameplay data; visual tiles are only its representation.

Workers contain worker entities and worker-specific behavior. Workers remain relatively dumb; mining, logistics, economy, and machine rules belong to their systems.

Mining owns mining gameplay but does not own resource physics.

Resources own logical resource representation. Logical resources are separate from physical representations.

Physics owns physical simulation and collisions and should remain replaceable/optimizable for Android.

Logistics owns transportation, storage, and jobs. JobSystem creates/manages jobs; WorkerAI selects suitable jobs.

Machines transform inputs into outputs and do not directly control UI, economy, or output physics.

Economy owns money, selling, and market rules.

Progression owns upgrades, unlocks, and prestige.

Simulation coordinates game-time progression. Not every system needs to update every frame.

Save owns persistence.

UI displays state and sends player commands; it should not directly manipulate gameplay internals.

# Communication rules

1. Rendering/UI does not own gameplay.
2. Worker does not directly control Economy.
3. Machine does not directly manipulate UI.
4. UI does not directly modify worker internals.
5. Mining does not directly manipulate physics internals.
6. Market does not need to know how workers operate.
7. Systems communicate through clear interfaces/events where practical.
8. Entities represent things; systems own gameplay rules and data.
9. A system should have one clear responsibility.
10. Do not create planned scripts merely because they appear in this document.

# Main flows

Mining: WorkerAI → JobSystem → MiningJob → MiningSystem → Terrain destroyed → Resources created → ResourceManager → PhysicsWorld

Machine processing: Machine → Processing complete → Resource created → EventBus / ResourceManager → PhysicsWorld

Logistics: LogisticsSystem / JobSystem → TransportJob → WorkerAI → WorkerMovement → WorkerInventory → Storage

Selling: Player / AutoSell → SellingSystem → Market → Money → EventBus → StatisticsSystem / UI

# Optional / future

Online functionality such as leaderboards is not part of the core architecture. If added later, it should be a separate optional system.

# Document authority

TechnicalArchitecture.txt is authoritative for system responsibilities, architectural rules, communication, ownership boundaries, and interactions.

GodotProjectStructure.txt is authoritative for Godot folder organization, scene organization, planned script locations, and asset/data organization.
