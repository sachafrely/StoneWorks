STONEWORKS — ROADMAP
====================

Purpose
-------
This is the practical implementation roadmap for building StoneWorks from the current architecture/documentation skeleton toward a playable Android game.

The GDD defines gameplay and design goals.
TechnicalArchitecture.txt defines system ownership and communication.
GodotProjectStructure.txt defines folders, scenes, nodes and script attachments.
Balancing.txt defines the current concrete resource-production rules.

The roadmap is intentionally sequential and simple. Do not implement the entire planned architecture at once. Build one small working layer at a time and verify it before moving on.

WORKING RULES
-------------

1. Finish the current roadmap step before starting the next major step.
2. Keep each implementation small enough to test.
3. Prefer working vertical slices over large amounts of disconnected code.
4. Keep gameplay ownership consistent with TechnicalArchitecture.txt.
5. Keep scene/node organization consistent with GodotProjectStructure.txt.
6. Use the three managers only for their defined ownership responsibilities.
7. Do not create new generic managers just to make code easier to find.
8. Keep logical resources separate from physical resource bodies.
9. Keep UI responsible for presentation and player commands, not gameplay rules.
10. Keep the scripted parallax system separate from gameplay and simulation state.
11. Test performance early, especially physical Stones/Gems and worker counts.
12. Update the documentation when an architectural or design decision actually changes.
